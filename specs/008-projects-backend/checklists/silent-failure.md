# Silent-Failure Checklist: BOQ entry and import (Amendment 2026-10-03)

**Purpose**: Interrogate whether the requirements covering this amendment's silent-failure paths are
written well enough to be implemented exactly one way. Every genuine risk in this amendment is a
failure that *looks like success* — an empty import reported as a working one, a tender doubled, a
percentage read as zero, a schedule appended twice — and requirements for that class of failure are
the ones where vagueness is least visible and most expensive.
**Created**: 2026-10-03
**Feature**: [spec.md](../spec.md) Amendment 2026-10-03 (FR-036 – FR-046); [plan.md](../plan.md)
Phases B1–B5; [research.md](../research.md) §15–§17

**Note**: This custom checklist is generated by the `/speckit-checklist` command based on feature context and requirements.
**Review Ownership**: This checklist is a reviewer-owned requirements-quality review artifact. Mark an item `[x]` only when the reviewer determines the requirements-quality criterion is satisfied.
**Marker Semantics**: `[x]` means the criterion has been reviewed and satisfied for requirements quality. It does not mean implementation work is complete.

## 1 · The empty import that reads as a successful one

- [ ] CHK001 Is the prohibition on a successful-but-empty response stated as a testable condition
      rather than as an intention? [Measurability, Spec §FR-036]
- [ ] CHK002 Are the three distinguishable empty conditions — bytes that are not a workbook, a
      workbook with no sheets, and sheets with no candidate rows — each given their own named
      outcome, or does one requirement cover all three? [Clarity, Spec §FR-036]
- [ ] CHK003 Does any requirement define the behaviour for a workbook that parses, has sheets, and
      has candidate rows of which **every one** is rejected? That response carries zero importable
      lines without being any of the three refusals. [Gap, Edge Case]
- [ ] CHK004 Is it specified whether `BOQ_WORKBOOK_EMPTY` applies to a `.xlsx` that genuinely has no
      sheets, or only to the `exceljs`-on-`.xls` case the amendment was written around?
      [Ambiguity, Contracts §Amendment]
- [ ] CHK005 Is the `exceljs` zero-sheet behaviour recorded as a measured observation with its date
      and the file it was measured against, so a library upgrade that changes it is detectable?
      [Traceability, Research §15]

## 2 · The tender that silently doubles

- [ ] CHK006 Is "the known schedule" defined — by header text, by column index, by a named range, or
      by the workbook's own `boq_type`/`boq_version` cells? Without a definition, two implementers
      produce two different importers and only one of them reads 312 lines.
      [Ambiguity, Spec §FR-042]
- [ ] CHK007 Are the requirements specific about whether columns 238–242 are excluded **by position**
      or by the general rule, given that the position is an artefact of one file and the next tender
      may place its second block elsewhere? [Clarity, Spec §FR-042]
- [ ] CHK008 Is "about 312 lines, not about 528" expressed as an assertable range, or does "about"
      leave the guard unimplementable? A tolerance that admits 528 admits the failure.
      [Measurability, Spec §FR-042]
- [ ] CHK009 Do the requirements state what happens when the identified schedule block cannot be
      found at all, as distinct from being found and empty? [Gap, Exception Flow]
- [ ] CHK010 Is there a requirement covering a workbook with **two legitimate** schedule blocks — a
      revised tender issued alongside the original — or is the single-block assumption stated as an
      assumption? [Assumption, Gap]

## 3 · The percentage read as zero

- [ ] CHK011 Is the distinction between "percentage found and equal to zero" and "percentage not
      found" required to be representable in the response, or only required not to be conflated in
      prose? [Clarity, Spec §FR-040]
- [ ] CHK012 Are the criteria for locating the `Excess (+)` figure specified well enough that
      "cannot be located with confidence" has an objective meaning? As written, confidence is the
      implementer's judgement. [Measurability, Spec §FR-040]
- [ ] CHK013 Do the requirements state what happens when the footer carries a percentage that
      parses but is implausible — negative, or above 100% — rather than only absent or present?
      [Gap, Edge Case]
- [ ] CHK014 Is it specified whether a located percentage that **fails** the reconciliation check
      (FR-045) should still be offered for confirmation, or treated as not found?
      [Conflict, Spec §FR-040 vs §FR-045]
- [ ] CHK015 Is the consequence of a silent zero quantified in the requirement itself — 2.46% and
      ₹7.37 lakh on the sample — so that a later reader cannot downgrade it to a nicety?
      [Traceability, Spec §FR-040]

## 4 · The schedule appended twice

- [ ] CHK016 Is idempotency stated as a requirement of the outcome ("a second confirm must not
      create additional rows") or only as a mechanism ("the batch is consumed")? A requirement
      written as a mechanism is satisfied by implementing that mechanism badly.
      [Measurability, Plan §B4]
- [ ] CHK017 Do the requirements specify that batch consumption and row creation must succeed or
      fail together, rather than leaving the ordering to the implementer? Consuming the batch before
      the transaction commits loses the schedule; consuming it after admits the double.
      [Clarity, Gap, Plan §B4]
- [ ] CHK018 Is the behaviour defined for two confirms of the same batch arriving **concurrently**,
      as distinct from sequentially? [Gap, Edge Case]
- [ ] CHK019 Is it specified how a caller distinguishes "this batch was already imported
      successfully" from "this batch never existed", given both return `BOQ_BATCH_NOT_FOUND`? The
      web plan requires showing the first as "already imported".
      [Conflict, Contracts §Amendment vs web FR-031]
- [ ] CHK020 Are requirements defined for importing a second schedule onto a project that already
      has one — appended, refused, or replacing? Nothing in the amendment says.
      [Gap, Coverage]

## 5 · The batch that vanishes between the two steps

- [ ] CHK021 Is the batch's lifetime specified as a value, or only as "a TTL"? An unstated TTL is
      untestable and will be chosen twice. [Measurability, Plan §B3]
- [ ] CHK022 Are the requirements explicit that an expired batch is reported as expired rather than
      as never having existed, so that a person who spent ten minutes reading a 312-line report is
      told what happened? [Gap, Clarity]
- [ ] CHK023 Is the single-instance constraint recorded as a **requirement or assumption of the
      design** rather than only as commentary, so that a future deployment change is forced to
      revisit it? [Assumption, Research §16]
- [ ] CHK024 Is the concurrent-batch cap specified with a number and with the behaviour on reaching
      it? [Gap, Measurability, Plan §B3]
- [ ] CHK025 Is it specified whether a batch is scoped to the project, the user, or neither — i.e.
      whether one user may confirm a batch another user validated? [Gap, Security]

## 6 · "Unplanned", and the partially planned line

- [ ] CHK026 Is "unplanned" defined by a specific condition — no dates at all, no finish date, or
      any missing programme field — rather than by the word? [Ambiguity, Spec §FR-037]
- [ ] CHK027 Do the requirements guarantee that a line with **some** programme fields set has
      exactly one home among Today, Delayed, To Be Delayed and Unplanned? A line with a finish date
      and no per-day quantity currently qualifies for two readings.
      [Gap, Edge Case, Spec §FR-037]
- [ ] CHK028 Are the four alert groups required to be mutually exclusive and jointly exhaustive, or
      is that only implied by the plan's phrasing "appears in exactly one of them"?
      [Clarity, Plan §B5]
- [ ] CHK029 Is the To-Be-Delayed computation's dependence on `perDayQty` reconciled with that field
      now being optional? The original definition reads "at risk based on Avg Qty Per Day vs required
      Per Day Qty", which has no meaning when the latter is null.
      [Conflict, Spec §FR-037 vs US4 AC and web §FR-026]
- [ ] CHK030 Are display requirements for an unplanned programme column specified in a way that
      excludes both an em dash and a zero, measurably? [Measurability, web §FR-026]

## 7 · The row cap, redefined

- [ ] CHK031 Is "candidate schedule rows" defined precisely enough to be counted one way only — does
      it include heading rows, and rows that will subsequently be rejected?
      [Ambiguity, Research §17]
- [ ] CHK032 Is the point in the pipeline at which the cap is applied specified, given that counting
      candidates requires having already identified the schedule block and parsed the whole sheet?
      [Clarity, Gap, Research §17]
- [ ] CHK033 Is the cap's purpose stated — protecting response time, or bounding memory — so that
      the number can be reasoned about rather than inherited? [Gap, Research §17 vs §4]
- [ ] CHK034 Is there a requirement bounding the **file size** accepted before parsing begins, as
      distinct from the row count applied after? A 50MB workbook is refused by neither.
      [Gap, Non-Functional]

## 8 · Cross-cutting requirement quality

- [ ] CHK035 Are the reconciliation requirements measurable — is "reconciles" defined as exact
      equality, or to a stated tolerance, given that the file's own figures carry float noise the
      amendment elsewhere refuses to trust? [Measurability, Conflict, Spec §FR-044 vs §FR-045]
- [ ] CHK036 Is the unit-normalisation rule specified as an algorithm with a stated outcome for the
      sample's 26 spellings, rather than as a list of examples? [Clarity, Spec §FR-041]
- [ ] CHK037 Is the requirement that `Excess (+)` resolve to **no unit** rather than to a unit named
      "excess" stated in the spec, or only in the plan and a task? [Traceability, Spec §FR-041]
- [ ] CHK038 Are the error and warning classes distinguished by a stated principle — a warning is a
      good row with unstated structure, an error is a row that cannot be imported — rather than by
      enumeration? [Clarity, Contracts §Amendment]
- [ ] CHK039 Is the audit requirement for an import specified as one entry per import with named
      contents, so that 312 entries would be a visible violation? [Measurability, Plan §Constitution]
- [ ] CHK040 Do the requirements state that a test skipped for want of the client's file reports as
      skipped and never as passed, as a requirement of the suite rather than as a note?
      [Clarity, Plan §Test strategy]
