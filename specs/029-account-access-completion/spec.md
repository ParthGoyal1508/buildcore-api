# 029 — Account access completion

Closes the gaps found in the 2026-10-16 review of account creation, sign-in and password
management. Backend: `buildcore-api`; screens: `buildcore-web`, same branch name.

Out of scope by decision (2026-10-16): extra account fields (mobile, reporting manager — these
stay on the HR employee record), sign-in by employee ID or mobile, an idle-session timeout.

## Requirements

**Accounts**

- **FR-001** A new account created without a role gets the default role. One role at most is the
  default (`Role.isDefault`, partial unique index); it is seeded as **General User** — My
  Workspace only, home page My Workspace — and cannot be deleted while it is the default.
- **FR-030** Deactivating an account revokes all its sessions and emails the holder. Saving an
  already-deactivated account again does neither.
- **FR-031** An account created with an admin-set password gets an "account ready" email naming
  the sign-in page and username — never the password.

**Passwords**

- **FR-005** One rule for every new password — invite, admin-created, self-service change, reset,
  admin temporary: at least 8 characters, an uppercase letter and a number, at most 128
  characters (`src/auth/password-policy.ts`). Sign-in accepts older passwords that predate it.
- **FR-006** Changing your own password signs out every other device and keeps the current one.
  Access tokens carry the session (refresh-token family) as `sid` for this.
- **FR-007** A changed password (self-service or reset link) is confirmed by email. The email
  carries no link.
- **FR-008** The self-service change endpoint has sign-in's per-address rate limit.
- **FR-010** Forgot Password: `POST /auth/forgot-password` with an email or username. The answer
  is identical whether or not an account exists; the email is sent without being awaited so the
  response time does not tell either.
- **FR-011** At most one self-service link per account per 60 s and 5 per hour, plus 5 requests
  per minute per address. Pending and deactivated accounts get nothing.
- **FR-012** Reset links are single-use, 30 minutes (self-service) or 24 hours (sent by an admin),
  newest-wins, dead once the account is deactivated, stored only as a SHA-256 hash. The token
  travels in request bodies, not API paths. The page carrying it sends `Referrer-Policy:
  no-referrer`, `Cache-Control: no-store`, `noindex`, and the service worker never caches it.
- **FR-013** Redeeming a link sets the password, clears any lockout, signs out every session and
  invalidates other outstanding links.
- **FR-014** An admin gets someone back in by either emailing a reset link (recommended; the
  current password keeps working until it is used) or setting a temporary password — generated by
  the server unless one is supplied, returned once, never logged, never emailed.
- **FR-015** The holder is emailed whenever an admin resets their password; the temporary
  password is not in it.
- **FR-016** An admin-chosen password must be replaced before anything else — after an admin
  reset as well as after admin creation (010 left the reset case advisory).
- **FR-017** An admin cannot reset the password of an account holding a permission they lack
  (My Workspace excepted), nor their own (Change password is for that), nor a pending or
  deactivated account.

**Home page**

- **FR-020** Each role may name a home page: a module key from `HOME_MODULES`, never a URL.
- **FR-021** A user lands on the home page of their roles — a chosen role's over the default
  role's, ties by role name — if they can open it, else on the first module they hold. This
  applies after sign-in, on every launch of the installed app (`/` → `/login` → `/home`), and to
  the Home links.

**Audit and the installed app**

- **FR-040** Audited: password changed, reset requested (with outcome), reset completed, admin
  reset (method, whether generated, by whom), and sign-out (previously never written).
- **FR-050** Responses carrying credentials or session state (`/auth/*`, `/users/me`) are
  `Cache-Control: no-store`; `/sw.js` is served `no-cache` so worker fixes reach installed apps.
